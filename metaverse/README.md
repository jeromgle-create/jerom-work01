# Jerom World — 실시간 멀티플레이 메타버스

브라우저에서 접속해 3D 광장을 돌아다니며 다른 접속자와 실시간으로 만나고 채팅하는 웹 메타버스입니다.
상위 레포의 Next.js 사이트와 **완전히 독립된 프로젝트**입니다 (별도 `package.json`, 별도 배포).

**운영 주소:** https://jerom-world.onrender.com (Render `jerom-world` 서비스, Singapore, Free 플랜, 배포 브랜치에 push 시 자동 재배포)

## 기능
- 닉네임·아바타 색상 선택 후 입장 (로그인 없음)
- 3D 월드: 교실배치도(안)를 바탕으로 구성한 학교 (학교 이름은 가상의 "한빛초등학교")
  - 배치 데이터는 `shared/layout.js` 한 곳에 있고, 클라이언트(화면·충돌·위치 표시)와 서버(구역 제한·채팅 대상)가 함께 사용
  - 배치도에 축척이 없어 방 순서·인접 관계는 도면대로, 크기는 표준화(교실 약 9×9m)
  - **실외** (`src/School.tsx`): 북관·남관과 사이의 중정(전래 놀이터 2곳·텃밭·손 씻기 시설·화단), 중앙현관,
    본관·유치원 동·체육관, 운동장(트랙·골대)과 스탠드·국기 게양대·구령대, 음수대·모래 놀이터·운동 기구,
    정문·후문·보안관실·분리수거장. 중정에서는 건물에 가리지 않도록 카메라가 위에서 내려다봄
  - **실내** (`src/Interior.tsx`): 13개 층, 방 113개. 방 종류(교실·돌봄·유치원·연구실·자료실·상담실·과학실·음악실·
    미술실·실과실·도서관·컴퓨터실·체육관·식당·보건실 등 30여 종)별 생성기가 크기에 맞춰 가구를 배치하고,
    문 앞은 자동으로 비워 둠
    - 북관 1~4층 / 남관 1~4층: 복도 북쪽에 방, 가운데 계단 (▲ 위층 · ▼ 아래층)
    - 본관 1~5층: 복도 양쪽에 방, 1층 식당·유치원·현관, 2층 교장실·교무실·도서관, 3층 체육관(무대)·실과실,
      4층 과학실·관람석, 5층 미술실·음악실
  - 초록 매트(각 동 입구, 1층 출구)와 계단 매트를 밟으면 이동, 왼쪽 위에 위치 표시 (예: 📍 본관 4층 · 과학실1)
  - 실내는 천장 없는 위에서 보기 시점(돌하우스), 카메라 쪽 바깥벽은 낮게 잘라 내부가 보임
  - 각 층은 같은 좌표계의 떨어진 구역(x=200부터 150 간격)이라 위치 동기화·근거리 음성·채팅이 그대로 동작
- **서울대공원 구역** (`src/Park.tsx`): 학교 정문 안쪽 주황 매트 "서울대공원 가는 길"을 밟으면 이동
  - 실제 지도가 아닌, 공개 안내 자료의 대표 시설(동물원·테마가든 장미원·식물원·캠핑장·호수·코끼리열차·스카이리프트)을 모티브로 단순화해 재구성
  - 정문 광장(매표소·코끼리열차 정류장·학교로 돌아가는 매트), 호수(오리배)와 둘레길, 동물원(기린·코끼리·사자·얼룩말·펭귄·홍학·어린이동물원),
    장미원(장미 터널·분수)·모란·작약원, 식물원 유리 온실, 자연캠핑장(텐트·모닥불), 잔디광장, 북쪽 산 배경
  - 호수를 도는 코끼리열차와 호수 위를 지나는 스카이리프트가 움직이고, 동물들은 우리 안을 천천히 돌아다님
  - **직접 탑승**: 정류장·탑승장 주황 매트를 밟으면 내 열차 칸/리프트 의자가 나타나 경로를 따라 이동하고 도착하면 내림
    - 코끼리열차(정문 → 호수 동쪽 둘레 → 동물원, 약 18초), 스카이리프트(호숫가 ↔ 동물원 정상, 공중 약 7m, 약 20초)
    - 서버가 "누가·언제·무엇에" 탔는지만 알리고, 모든 화면이 같은 경로 함수(`shared/layout.js`의 `ridePose`)와 서버 시각으로 위치·높이를 계산
      → 다른 사람도 탑승 모습을 그대로 보고, 늦게 접속한 사람도 탑승 중인 사람을 봄
    - **친구와 함께 타기**: 첫 사람이 타면 열차(8초)·리프트(4초)가 정류장에서 출발을 기다리고, 그 사이 같은 매트를 밟은 사람은 같은 차량에 탑승
      (코끼리열차 3칸 × 2명 = 최대 6명, 리프트 2인승). 정원이 차거나 출발하면 다음 사람은 새 차량. 좌석·출발 시각은 서버가 배정
    - 탑승 중 이동 키는 잠기고 화면 왼쪽 위에 "출발까지 n초 · m명 탑승" / "타는 중 · 남은 시간" 표시, 내릴 때는 나란히 하차, 채팅·음성은 그대로 사용
    - 서버 검증: 정류장 근처에서만 탑승, 중복 탑승 불가, 도착 신호가 없으면 자동 하차 처리
  - 학교 운동장에서도 담장 너머로 공원의 산이 보임. 공식 로고·상표 이미지는 사용하지 않음
- 이동: WASD / 방향키, 모바일은 가상 조이스틱
- 실시간 동기화: 다른 접속자의 위치·방향 (초당 15회, 보간 처리)
- 채팅: 탭 3개 + 머리 위 말풍선(5초, 메시지를 받은 사람에게만 보임)
  - **근처**: 보내는 순간 반경 3m·같은 방 안에 있는 사람에게만 전달 (벽 너머는 제외)
  - **만남**: 3m 이내에서 1.5초 이상 머무르면 대화 그룹 자동 생성 (A–B, B–C가 가까우면 A·B·C 한 그룹).
    4m 넘게 멀어지면 빠지고, 만남마다 대화 기록이 따로 남음(읽기 전용). 같은 사람을 다시 만나면 이전 대화방이 이어짐
  - **전체**: 접속자 모두에게 전달, 입·퇴장 알림
  - 받는 사람은 **서버가 위치로 결정**하므로 멀리 있는 사람은 대화를 받을 수 없음
- **근거리 음성 채팅**: 🎙️ 버튼으로 참여 → 마이크 켜기/끄기, 나가기
  - 거리 3 이내는 최대 음량, 멀어질수록 작아지다 16 이상이면 들리지 않음 + 좌우 방향감
  - 말하는 사람 이름표에 🔊·초록 테두리, 마이크 꺼짐은 🔇
  - 접속자 목록에서 특정 사람만 내 쪽에서 음소거
  - 동시 참여 최대 8명 (`MAX_VOICE`)
- 접속자 수 / 목록, 자동 재연결
- 라이트/다크 테마 자동 대응

## 구조
| 경로 | 역할 |
|---|---|
| `server/index.js` | Express + Socket.IO 서버. 빌드된 클라이언트(`dist/`)도 함께 서빙 → **서비스 1개로 배포** |
| `src/` | React + React Three Fiber 3D 클라이언트 (Vite) |
| `Dockerfile` | Fly.io / Railway / Render(Docker) / VPS 공용 이미지 |

### 음성 구조와 한계
- 오디오는 **접속자끼리 직접(WebRTC P2P)** 전송되고, 서버는 연결 정보(시그널링)만 중계합니다 → 서버 부하·비용 거의 없음.
- 참여자마다 다른 참여자 전원과 연결하므로 8명 안팎이 적정입니다.
- 기본은 공개 STUN 서버만 사용합니다. 회사 방화벽·일부 모바일 망처럼 직접 연결이 막힌 환경에서는 소리가 안 들릴 수 있으며, 이때는 TURN 중계 서버가 필요합니다.
  TURN 서비스를 구한 뒤 Render 환경 변수 `ICE_SERVERS`에 JSON으로 넣으면 코드 수정 없이 적용됩니다:
  ```json
  [{"urls":"stun:stun.l.google.com:19302"},{"urls":"turn:<host>:3478","username":"<user>","credential":"<pass>"}]
  ```
- 마이크는 HTTPS 주소에서만 동작합니다 (Render 주소는 HTTPS).

서버 보호 장치: 좌표 범위 제한, 닉네임 16자·채팅 200자 제한, 채팅 도배 방지(0.7초), 최대 접속자 수(`MAX_PLAYERS`, 기본 50), 음성 참여자끼리만 시그널링 중계·메시지 크기 제한.

## 로컬 실행
```bash
cd metaverse
npm install
npm run dev        # http://localhost:5173 (서버 :3001 자동 연동)
```
프로덕션 모드 확인:
```bash
npm run build && npm start   # http://localhost:3001
```
브라우저 탭 2개로 접속하면 실시간 동기화를 바로 확인할 수 있습니다.

## 외부 배포 (택 1)

> Vercel은 WebSocket 서버를 상시 실행할 수 없어 이 프로젝트에는 맞지 않습니다. 아래처럼 **Node 서버를 상시 실행하는 호스팅**을 사용합니다.

### A. Render (권장 · 무료로 시작)
1. https://render.com 가입 → GitHub 연결
2. **New → Web Service** → 이 레포 선택
3. 설정값
   | 항목 | 값 |
   |---|---|
   | Branch | 배포할 브랜치 |
   | Root Directory | `metaverse` |
   | Runtime | Node |
   | Build Command | `npm ci --include=dev && npm run build` |
   | Start Command | `npm start` |
   | Health Check Path | `/healthz` |
   | Environment | `NODE_ENV=production` |
4. 배포 완료 후 `https://<서비스명>.onrender.com` 으로 누구나 접속 가능

무료 플랜은 일정 시간 접속이 없으면 잠들고, 첫 접속 시 깨어나는 데 수십 초가 걸립니다. 상시 운영하려면 유료 플랜이 필요합니다.

### B. Docker 지원 호스팅 (Fly.io, Railway 등)
`metaverse/Dockerfile`을 그대로 사용합니다. 컨테이너는 `PORT`(기본 8080)에서 대기합니다.
```bash
cd metaverse
docker build -t jerom-metaverse .
docker run -p 8080:8080 jerom-metaverse
```

### C. 임시 공유 (내 PC에서 바로)
로컬에서 `npm run build && npm start` 후 Cloudflare Quick Tunnel 등으로 임시 공개 URL을 만들 수 있습니다.
```bash
cloudflared tunnel --url http://localhost:3001
```
PC를 끄면 접속이 끊기므로 테스트 용도로만 적합합니다.

## 별도 레포로 분리하기 (선택)
상위 레포 루트에서:
```bash
git subtree split --prefix=metaverse -b metaverse-only
```
생성된 `metaverse-only` 브랜치를 새 GitHub 레포에 push하면 커밋 이력이 유지된 독립 레포가 됩니다. 이 경우 Render의 Root Directory는 비워 둡니다.
